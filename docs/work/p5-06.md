## 근거 (REA 정본: docs/rea/arch_families.md, 2026-10-18)

1. 엔진 실행은 `general.architecture` 문자열 → 클래스 dispatch
   (`SOURCE: src/poly/engine.cpp:808-816` — `glm5-next`/`glm5next`→Glm5Next, `qwen35moe`→Qwen35,
   `gemma4`→Gemma4, `deepseek4`→DeepSeek4, 밖은 throw "which this engine does not run").
2. 실행 계층은 shape를 **파일에서 읽는다** (`SOURCE: src/poly/engine.cpp:674-697`,
   `meta_in`은 arch 값 + "." prefix — engine.cpp:646-653). 하드코딩 prefix 아님.
3. artifact guard(`check_architecture`, gguf_reader.hpp:796-812)는 qwen4exp/qwen35moe만 통과,
   그 밖은 name 거부. p4-01 §근거 2·p4-03 AC3의 "compiled 프리셋" 표현은 이 계층 한정.
4. Gemma4 실행 키 어휘: `gemma4.` prefix + `attn_norm`, `attn_q/k/v`, `attn_q_norm/k_norm`,
   `attn_output`, `ffn_norm`, `ffn_gate/up/down(.weight)`, `ffn_*_exps.scale`, `ffn_gate_inp`,
   geometry 키 `attention.sliding_window`, `attention.key_length(_swa)`,
   `attention.sliding_window_pattern`, `rope.freq_base(_swa)`, `final_logit_softcapping`
   (`SOURCE: src/poly/gemma4.cpp:48-82,197-211`).
5. 현행 CLI: `general.architecture` prefix는 `guard_keys["architecture"]`로 선택 (`main.py:601,620`).
   Qwen1.5-MoE·Mixtral 아키텍처 클래스는 엔진에 실재하지 않음 (`Grep src/poly/` 0건) — p4-03 실측 load 거부.

## AC3 매핑 설계 (2026-10-18, AC2 실측 inventory 한정 — never-invented)

- `hf_layer_id` 확장: `model.(language_model.)layers.N` — Gemma4 prefix 실측.
- fused expert pattern 확장: `model.language_model.layers.N.experts.{gate_up_proj,down_proj}`
  (`mlp.` 없음, shape [NE,2FF,H]/[NE,H,FF] — Qwen1.5 fused와 동일 slicing, build_expert_map 재사용).
- `GLOBAL_DENSE` gemma4 항목 (실측): `model.language_model.embed_tokens.weight`→`token_embd.weight`
  (transpose), `model.language_model.norm.weight`→`output_norm.weight`. `lm_head` 부재(tied) — 매핑 없음.
- `LAYER_DENSE` gemma4 항목 (실측): `input_layernorm`→`attn_norm`, `post_attention_layernorm`→`ffn_norm`,
  `router.proj.weight` [128,2816]→`ffn_gate_inp.weight`. `pre/post_feedforward_layernorm(_1/_2)`,
  `layer_scalar`, `router.scale`, `router.per_expert_scale` — engine Gemma4 키 어휘(gemma4.cpp:197-211)
  에 없는 실측 키: 매핑·발명 금지, emit builder가 skip.
- dense MLP: sliding layer에만 실측 (full layer dense absent) — emit builder의 optional tensor
  skip 규칙이 그대로 성립. dense_type gate: 2112×2816=5,942,016 elements > 64 MB → stream.
- `derive_geometry(prefix="gemma4")` 확장 (config 실측 → GGUF 키): `block_count`=30,
  `embedding_length`=2816, `expert_count`=128, `expert_used_count`=8(top_k),
  `expert_feed_forward_length`=704(moe_intermediate), `expert_shared_feed_forward_length`=2112
  (sliding dense 실측), `attention.head_count`=16, `attention.head_count_kv` per-layer 배열
  (swa=8/global=2 — engine of_layer 허용), `attention.key_length`=512(global)/
  `key_length_swa`=256, `attention.value_length`=key_length (`attention_k_eq_v=True` 실측),
  `attention.sliding_window`=1024, `attention.sliding_window_pattern`=5(layer_types 실측 패턴
  5 sliding + 1 full), `rope.freq_base`=1e6, `rope.freq_base_swa`=1e4,
  `final_logit_softcapping`=30.0, `attention.shared_kv_layers`=0.
- **충돌 실측 기록**: `embedding_length_per_layer_input` engine must=0 vs HF
  `vocab_size_per_layer_input`=262144(비0). 0을 쓸 수 없음(발명). AC4 엔진 load는 실측 게이트:
  engine guard `check_architecture`는 gemma4 name 거부(gguf_reader.hpp:796-812, 표 §3),
  실행 계층 Gemma4 class는 CUDA/HIP 전용(model_family.hpp:52-62) — AC4 acceptance는
  reference verifier(gguf_reader parse + canonical_xcheck 왕복 + our verify) 정본,
  engine 실행은 GPU·인간 게이트로 기록.
- 테스트: `tests/test_hf_gguf_map.py` 확장 — shard1 헤더 실측 inventory JSON(작은 fixture)으로
  매핑 전수 + engine 어휘 밖 키(pre/post feedforward, layer_scalar) skip + must-0 충돌 케이스.
- guard-keys 프리셋: `scripts/p5_gemma4_guard.json` — 위 derived 값 전수 (config 실측 경유).
- AC4 chain: `convert <dir> --emit-gguf --guard-keys p5_gemma4_guard.json` → GGUF prefix
  `general.architecture`=gemma4 → harness gguf_reader parse tensor/shape/offset 일치 +
  canonical_xcheck Q2_0 왕복 + our verify PASS + engine guard 거부 실측 메시지 기록.
