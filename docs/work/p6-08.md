### 형식 선택 일원화 (`quant/select.py`)

```text
select_dense_quant(n_el, dense_type, ne0, ndim, force_f32) -> str        # 지금의 _dense_select
select_pack_quant(shape, dense_type) -> str                              # 단일 파일 emit (Q4_0 32배수 거부 포함)
select_expert_quant(row_len, n_elems, has_plane, ladder) -> ExpertQuant | None
ExpertQuant = (type_name, row_len, n_elems) + quantize(f32, plane_row)   # 이름·함수·형태가 항상 짝
```

리뷰 반영(2026-10-22): `select_pack_quant`와 `select_dense_quant`는 pack 게이트 `_pack_accepts` 하나를 같이 쓴다.
`ExpertQuant`는 선택 때 확인한 `row_len`·`n_elems`를 들고 있어서 `quantize()`에 다시 넘기지 않는다.

- `ExpertQuant`는 **타입 이름과 양자화 함수를 한 객체로 돌려준다.** 호출하는 쪽이 따로 고르지 못한다.
- `has_plane=False`면 `("Q2_0", quantize_q2_0_stream)` (지금과 같음).
- `ladder`로 호출 지점별 허용 사다리를 받는다.
  - fused gate/up, per-expert: `("Q4_K", "Q4_0")` — Q4_K는 `row_len % 256 == 0`이고 `n_elems % 256 == 0`일 때만, 아니면 Q4_0는 `row_len % 32 == 0`이고 `n_elems % 32 == 0`일 때만.
  - **fused down: `("Q4_0",)`** — 지금 코드가 `plane`이 있으면 무조건 Q4_0이므로 바이트를 지키려고 그대로 둔다. (Mixtral처럼 `ff % 256 == 0`인 모델에서 Q4_K가 더 맞을 수 있으나 동작 변경이라 이번 범위 밖 → 백로그.)
- 근거 주석(`gguf_reader.hpp:505 pin c566ff4`, `docs/work/p5-08.md` 사다리)은 함수와 함께 옮긴다.

### 허용된 동작 변경 (이 한 가지)

expert 슬롯에서 imatrix 평면이 있는데 **행 길이가 32의 배수가 아니면** 예전 코드는 fused gate/up(`h % 256 != 0`)과
fused down(평면이 있으면 무조건 Q4_0)에서 `% 32` 검사 없이 Q4_0을 골라 엔진이 못 읽는 파일을 냈다
(per-expert 경로는 이미 막고 있었음). 통합 후에는 세 경로 모두 같은 규칙을 따른다: 사다리가 안 맞으면 Q2_0, **Q2_0도 엔진 load 게이트
(type id 42, `be=64`, `gguf_reader.hpp:232-235` 핀 `c566ff4`)를 못 넘으면 파일을 쓰지 않고 종료 코드 3으로 거부**한다.
(리뷰 전 초안은 무조건 Q2_0이었는데, `row_len % 64 != 0`이면 그 Q2_0도 엔진이 못 읽고 `n_elems % 64 != 0`이면
양자화 도중 `ValueError`가 났다.) 평면이 없는 Q2_0 경로에도 같은 거부가 적용되며, 예전에는 이 입력이 엔진이
못 읽는 파일을 냈거나 도중에 예외로 끝났다.
기준 fixture·기존 테스트에는 이런 입력이 없고, `tests/test_select_quant.py`로 고정했다. 이 외의 바이트 변화는 허용하지 않는다.

`stream`은 `quant`를 부르지 않고 바이트만 읽는다(양자화 연결은 emit 단계 함수가 한다).
