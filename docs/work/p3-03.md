## 근거

- Q4_0 contract: `docs/rea/struct_layouts.md §2` (type id 6, 32 elems/block, 18 B),
  `canonical_xcheck.py` `to_s4_q4_0` (pin c566ff4): 저니블=앞 반, 고니블=뒤 반,
  codebook −8..7, scale fp16. `from_s4_q4_0`: `v=(code−8)·d` (bias는 integer 안에서).
- 엔진 build는 MAPPINGS로 dense를 tensor_entry로 기록 (`strata_pack.py:268-306`):
  codes = `pack_codes(codes,4)` (LSB-first 2 codes/byte), scales = fp16
  (`choose_scale_dtype` — Q4_0 d는 fp16에서 정확), form S4, code_bias −8.
- 우리 S4 평면 기계는 IQ4_NL로 이미 검증됨 (`p3-01`, `iq4_nl_planes`). Q4_0은 같은
  S4 + bias −8 + codebook 없음.
- 양자자 byte-identity reference: **gguf-py `quants.quantize`** (엔진 writer는 Q2_0 전용
  — `gguf_writer.py`에 Q4_0 quantize 없음). gguf-py는 엔진이 C++ 대비 검증한 독립 구현
  (`canonical_xcheck.py:598-601` 근거).
- expert arena는 Q2_0 전용 (`pack_layer.py:46` ROLE_BYTES Q2_0 산수) — **expert Q4_0은
  엔진 pack 범위 밖**. 이번 Goal은 dense만.

## Resume-Notes (2026-10-16, 세션 종료)

- **정찰 완료 (probe, gguf-py quants.py:220-237)**: gguf-py `quantize(Q4_0)`는 **signed max**
  규칙 — `d = max/−8` (signed), `qs = trunc(w·(1/d)+8.5)` clip 0..15. 엔진/ggml의 **amax** 규칙
  (`d = amax/8`, `qs = rint(w/d)+8`)과 **다름**. nibble layout(저니블=앞반, 고니블=뒤반)과
  dequant `(code−8)·d`는 엔진 `dequant.hpp:88`과 gguf-py가 **일치**.
- **엔진에는 quantizer가 없다** (`gguf_writer.py`는 Q2_0 전용, C++는 dequant만) — 엔진은
  llama.cpp 산출 GGUF를 소비한다. AC1의 byte-identity reference(llama.cpp quantize_q4_0)는
  로컬에 없다.
- **AC1 재정의(재개 시 첫 수)**: contract = 엔진 dequant 왕복 — `d = fp16(amax/8)`,
  `code = clip(rint(w/d)+8, 0, 15)`, `dequantize_q4_0`(dequant.hpp:88 전사)로 `(code−8)·d`
  복원 + 양자화 오차 바운드 `|w−v| ≤ d/2`. gguf-py quantize는 contract **아님**
  (signed-max divergence — spec_draft에 HYPOTHESIS로 기록). AC2~AC5(엔진 acceptance +
  golden byte-identical)는 그대로 유효 — engine acceptance가 실 acceptance 게이트.
