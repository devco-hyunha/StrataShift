## 한 줄 결론

이미 있는 p6-04 `llama-imatrix` 산출물과 p6-05 emit 경로로 **품질 실측·엔진 왕복·인간 서명**을
닫는다. 산출물을 우리 코드로 직접 만드는 스트리밍 축적(p6-03 AC4)은 성격이 달라 본 Goal에
넣지 않고 ROADMAP 백로그로 둔다.

## In / Out

- In: p6-04 verified `imatrix.gguf`, p6-05 HF fused imatrix emit, plain RTN 대비 PPL/KLD,
  엔진 verify+로드, API serve 왕복, ACCEPTANCE 서명.
- Out: 우리 코드의 스트리밍 forward 축적(p6-03 AC4 백로그), IQ codebook(`p6-06` 백로그),
  엔진 pin 상향, Windows 자동 설치(handoff 단계 3).

## 설계 요약

1. full product emit: `--imatrix .local/out/p6-04-imatrix-20261021/imatrix.gguf`로
   HF fused 실모델 emit (p6-05 "gate 발화 순서" 3번에서 이관).
2. 엔진 acceptance: strata-gguf / dequant / 로드 왕복 + PPL/KLD (plain RTN vs imatrix).
3. API serve: calibration producer Q4_K 산물 vs plain — 품질 응답 비교.
4. ACCEPTANCE.md 인간 서명 — opt-in `--imatrix` 제품 게이트.

| AC | 원문 출처 | 내용 | 종류 |
| --- | --- | --- | --- |
| AC1 | p6-03 AC5 | PPL/KLD 실측 비교 (plain RTN vs calibration producer), engine chain sweep 재통과 | 품질 측정 |
| AC2 | p6-03 AC6 | API serve 왕복 품질 비교 | 품질 측정 |

PPL/KLD는 AC1(단일 파일·producer 대비)·AC3(엔진 로드 포함)로 나눈다.

## 테스트 계획

- 회귀: plain RTN (`--imatrix` 없음) golden byte 불변 유지.
