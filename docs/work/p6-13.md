## In / Out

- In
  - `stratashift build-engine [--gpu] [--cuda-arch N] [--yes] [--dry-run] [--engine-src DIR]`
  - 설치 묶음 정리: `engine-cpu` = [엔진 소스, 핀 llama.cpp 소스, CMake, MSVC], `engine-gpu` = `engine-cpu` + [CUDA 13.0]
    (3d의 `engine-build` 묶음을 이 둘로 바꿈)
  - 핀 llama.cpp 소스 항목: 있으면 통과, 없으면 GitHub 커밋 zip → 내용 해시 확인 → `.local/llama.cpp/llama.cpp-<커밋>/`
  - 빌드: `vcvars64.bat` → CMake 구성(Ninja) → 빌드, 실패하면 한 번 다시(setup.py `cmake_build` :4096-4122 방식)
  - CUDA 실제 설치(허락됨) → `strata-poly.exe` 빌드 → 작은 fixture 불러오기 시도, 결과 또는 오류를 그대로 기록
  - `C:\opt\data` junction 없이 전체 `pytest` (junction 처리 방법은 실행 직전에 사용자에게 확인)
  - Windows 설치·실행 문서(`docs/USAGE.md` 또는 등록한 위치), 자동 설치가 실패했을 때 손으로 따라 하는 절차
- Out
  - 엔진 파일 수정, 핀 상향, AMD/Intel GPU
  - 실제 모델(대형) 실행 성능 — 4 GB VRAM에서 되는지만 기록

## 설계 (요약)

- 새 파일 `src/stratashift/install/build.py`: 빌드 명령 조립(순수 함수 `build_commands(paths, gpu, arch, nvcc, ninja)`)과
  실행(`run_build`), VS 동봉 Ninja 찾기. CLI는 `cli/main.py`의 `build-engine` 하위 명령.
- 빌드 폴더는 `<엔진 빌드>`(`STRATASHIFT_ENGINE_BUILD`, 기본 `.local/polystrata/build`) 하나. `--gpu`는 같은 폴더를 CUDA ON으로 다시 구성한다.
- `--cuda-arch` 기본값: `nvidia-smi --query-gpu=compute_cap` (8.6 → 86). 못 읽으면 거절하고 옵션을 안내한다.
- 리눅스: 빌드 명령과 손으로 하는 방법만 알린다(자동 설치처럼 Windows 전용).
