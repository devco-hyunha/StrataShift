## 한 줄 목표

HF safetensors MoE 모델(실제 HF naming, fused gate_up_proj, BF16)을 스트리밍으로
엔진 GGUF(expert Q2_0 + dense 키 매핑)로 변환하고, qwen4exp geometry HF fixture에서는
엔진 체인 full acceptance, Mixtral geometry fixture에서는 엔진 reference verifier
acceptance를 얻는다.

## 프로젝트 목적에 따른 방향 (Phase 4 설정 근거)

Phase 0~3은 엔진과 엔진 특화 모델(qwen4exp geometry)에 대한 분석·수락이었다.
AGENTS.md 목표("임의의 MoE .safetensors 모델을 레이어/Expert별로 스트리밍으로 읽은 뒤
PolyStrata 포맷으로 변환")의 "임의" 칸이 아직 미개척이다. 입력 레이어는 HF naming

Phase 4 = 입력 일반화: HF naming → engine GGUF naming, fused split, BF16.

## 근거 계약 (pin c566ff4, read-only)

1. **엔진 GGUF 키 어휘** — `src/core/layout.cpp:60-110`: layer suffix 집합
   `ffn_gate_exps/ffn_up_exps/ffn_down_exps.weight`, `ffn_gate_inp.weight`,
   `ffn_{gate,up,down}_shexp.weight`, `ffn_gate_inp_shexp.weight`(Bf16InF32),
   GDN `attn_qkv/attn_gate/ssm_out/ssm_conv1d/ssm_alpha/ssm_beta`, QSA
   `attn_q/attn_k/attn_v/attn_output`, `indexer.{q,k}_proj`, 1-D
   `hc_{attn,ffn}_norm`, `ssm_a`, `ssm_dt.bias`, `ssm_norm`, `attn_{q,k}_norm`,
   `indexer.{q,k}_norm`. prefix는 `blk.<layer>.` (`LayerView::name`, layout.cpp:110).
2. **엔진 가드** — compiled geometry(`embedding_length=2560`, `block_count=48`,
   ssm/att/indexer/hc 키) — `docs/rea/struct_layouts.md` §1 VERIFIED (p3-01).
   엔진은 qwen4exp geometry만 수락 → Mixtral geometry는 strata-gguf 가드 대상 아님
   (FAIL이 아니라 scope 밖 — reference verifier로 acceptance).
3. **HF naming 실측** — `.local/models/mixtral-tiny.safetensors` (21 tensors, BF16,
   2 layers, NE=4, H=64, FF=128): `model.embed_tokens.weight`, `lm_head.weight`,
   `model.layers.L.{input_layernorm,post_attention_layernorm}.weight`,
   `model.layers.L.self_attn.{q,k,v,o}_proj.weight`, `model.layers.L.mlp.gate.weight`,
   `model.layers.L.mlp.experts.gate_up_proj` (NE,2FF,H),
   `model.layers.L.mlp.experts.down_proj` (NE,H,FF).
4. **expert_map.py 패턴** (p1-01): Mixtral/Qwen2MoE/GPT-OMoe/legacy/fused — fused
   expert `e`는 연속 row block `[e·prod(shape[1:]), (e+1)·prod(shape[1:]))`.
5. **BF16→F32**: BF16 = F32 상위 16비트 → `uint16 << 16` → f32 view (numpy).
   F16→F32는 numpy native. 양자화 스트림 입력은 F32로 정규화 (기존 quantizer 계약 유지).
6. **fused gate_up split**: expert `e`의 gate = rows `[0,FF)`, up = rows `[FF,2FF)`
   (row-major (NE,2FF,H)에서 연속 run). GGUF fused shape `(in,out,NE)` + expert
   연속 run — struct_layouts §1 VERIFIED (p3-02).

## Emit 규칙

- expert: HF fused `(NE,2FF,H)` → expert별 gate/up slice 스트리밍 → Q2_0 stream →
  `blk.L.ffn_gate_exps.weight` shape `(H,FF,NE)`; down `(NE,H,FF)` →
  `blk.L.ffn_down_exps.weight` shape `(FF,H,NE)`. (기존 quantize_q2_0_stream, p3-02 계약)
- dense 매핑 (HF → engine GGUF, layout.cpp 근거):
  `model.embed_tokens.weight`→`token_embd.weight`, `lm_head.weight`→`output.weight`,
  `input_layernorm`→`blk.L.attn_norm`, `post_attention_layernorm`→`blk.L.ffn_norm`,
  `mlp.gate`→`blk.L.ffn_gate_inp.weight`, `self_attn.{q,k,v,o}_proj`→
  `blk.L.{attn_q,attn_k,attn_v,attn_output}.weight`, shared_expert →
  `blk.L.ffn_{gate,up,down}_shexp.weight`, `shared_expert_gate`→
  `blk.L.ffn_gate_inp_shexp.weight` (Bf16InF32 — dtype 게이트: BF16 바이트 유지).
- dense dtype: BF16/F16 → F32 정규화 후 기존 dense_type 프리셋 게이트 적용
  (p3-03~p3-09 pack gate 그대로).
- guard keys는 HF 헤더에서 **산출** (never invented): `embedding_length`=embed_tokens
  shape[1], `block_count`=layer 수, `expert_count`=NE, `expert_feed_forward_length`=FF,
  `attention.head_count`=q_proj shape[0]/head_dim, `attention.head_count_kv`=
  k_proj shape[0]/head_dim. qwen4exp fixture는 compiled geometry 키 전부를 HF 헤더
  산출로 채운다.
- CLI: `convert --emit-gguf --hf-emit` (HF naming 자동 감지: expert_map hits).
