## 한 줄 목표

우리 변환 산출물 GGUF에 tokenizer 메타(`tokenizer.ggml.*`)를 실어 발행하고, PolyStrata
`serve/server.py`(OpenAI `/v1/chat/completions`)가 우리 산출물을 로드·구동·API 응답하는
end-to-end 종점 스모크를 실측으로 통과/기록한다. 변환기 "모양만"이 아니라 엔진 RUN + API가
v1.0.0 종점 AC에 포함된다.

## 설계 (emit 규칙 — pseudocode)

1. `cli/main.py` emit builder에 tokenizer 메타 섹션 추가: HF `tokenizer.json` 실측 파싱
   (`model.model` = "gpt2"-type BPE vocab/merges/token_type, `added_tokens` special ids) →
   GGUF 헤더 key 어휘 전사:
   - `tokenizer.ggml.model`, `tokenizer.ggml.tokens`, `tokenizer.ggml.merges`,
     `tokenizer.ggml.token_type`, `tokenizer.ggml.pre` (= `gemma4` — 엔진 `MODELS` 실측
     어휘, 발명 금지), `tokenizer.ggml.added_tokens`→`*_token_id` pairs,
     `tokenizer.ggml.bos/eos/eot/eod_token_id`, `tokenizer.chat_template` (HF
     `chat_template.jinja` 실측 그대로).
2. never-invented 게이트: HF tokenizer 파일이 fixture/guard의 measure-equal이 아니면
   발행 거부 (p5-08 rope gate와 동형 규칙 — `cli/main.py::_gemma4_rope_freqs` precedents).
3. emit 순서: GGUF header n_kv는 우리 parser가 셀 수 있는 크기로 증가 — 우리
   `ingest/gguf.py` round-trip gate + 엔진 `gguf_reader.py` parse match 게이트로 정합.
4. 스모크는 `extract()`의 산출물 계약에 의존하지 않고 **GGUF 단일 파일**으로 API가
   서브를 구성하는지 검증하는 것을 정본 AC로 한다 (pack 없이 GGUF + run config로
   tokenizer 디렉터리를 만들 수 있는지 — 실측으로 판정).
5. mini fixture에는 HF tokenizer가 없으므로, AC1은 실모델 tokenizer 확보 후 mini에
   실측 tokenizer를 주입한 사본(`.local` 전용)으로 스모크 계단을 만든다.
