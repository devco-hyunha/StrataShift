## Emit 규칙

- expert: per-expert refs (expert_map p1-01) → expert 순서 gate/up/down 스트리밍 →
  `blk.L.ffn_{gate,up}_exps.weight` shape `(H,FF,NE)`, `blk.L.ffn_down_exps.weight`
  shape `(FF,H,NE)` (main.py:745-775 per-expert emit 경로, p4-01).
- dense: p4-01 테이블 매핑 (attn_norm/ffn_norm/ffn_gate_inp/attn_q,k,v,output/
  token_embd/output/output_norm). Qwen1.5-MoE는 shared expert·GDN·QSA·indexer·hc 없음.
- guard keys: `embedding_length=2048`(embed shape[1] 산출), `block_count=24`(layer 수
  산출), `expert_count=60`·`expert_feed_forward_length=1408`(gate_proj shape 산출 —
  per-expert: gate (FF,H) → FF=shape[0], H=shape[1]), `attention.head_count=16`,
  `head_count_kv=16` (q/k_proj shape[0] // head_dim, head_dim=config.json 실측 128).
  CLI는 모델 디렉토리의 `config.json`에서 head_dim 산출 (미측정 시 head_count 미산출 —
  cross-check는 산출된 키만 비교, main.py:575-588 규칙).
- CLI: `convert <dir> --emit-gguf --hf-emit --guard-keys <preset>` — preset은
  config.json 실측값에서 harness가 작성 (never invented).

Goal 안에서 닫은 원인 3건 (기록만 하고 넘기지 않음):
1. **F32 passthrough 스트리밍 BF16 미확대** — `emit_dense_stream`의 F32 분기가 raw BF16
   chunk를 F32 type으로 기록 → embed/lm_head 절반 크기 (GGUF 10.53→9.29 GB, delta가
   정확히 embed F32 크기). 2-run 크기 비교로 검출, chunk별 `_to_f32` widening으로 수정.
2. **dirty page 누적 ENOMEM (Errno 12)** — tmp GGUF writeback 지연으로 3.57 GB 지점에서
   작은 read가 실패 (7.7 GB WSL). `add_tensor`/`add_tensor_stream`에 256 MB 주기 fsync
   (p3-09 convention) 추가.
3. **sha256 full-load OOM (RC=137)** — R7의 `read_bytes()`가 10.5 GB GGUF를 통째로 읽음
   → 절대 규칙 위반, 1 MB chunk 스트리밍 sha256으로 교체.

한정 (근거 §4). 엔진 구동 실측은 qwen4exp fixture 전용 (p4-01/p4-02 chain).
